## Root Cause Analysis

### 1. No Alpaca Credentials Configured (CRITICAL)

The paper runner requires `ALPACA_API_KEY` + `ALPACA_API_SECRET` (from env vars or `broker/.env`).

- `broker/.env` does **not exist**
- No `ALPACA_*` environment variables are set in the execution environment
- Without credentials, `AlpacaClient()` fails at construction → runner aborts before logging any trade

**Evidence:**
```
broker/.env → file not found
printenv | grep -i alpaca → (empty)
```

### 2. No Scheduled Execution

`h10_paper_runner.py` is a one-shot CLI script with no cron job, Paperclip routine, or any automated trigger configured. After the single dry-run on 2026-03-16, it was never invoked again.

The runner must be called daily (end of day) manually or via a scheduler to capture signals and log trades.

### 3. QUA-3 Metrics Are Backtest Numbers, Not Live Paper Trades

QUA-3 reports: "6 live paper trades executed, 67% win rate, +3.2% P&L"

Cross-referencing against `backtests/H10_CryptoEQLReversal_v2_2026-03-16.json`:
- OOS win rate: **67.31%** ← matches QUA-3 exactly
- OOS trade count (partial): consistent with "6 trades" in a sub-period window

The trade log has **0 live paper trade entries**. QUA-3 metrics were drawn from the backtest results file, not from actual paper trading execution.
