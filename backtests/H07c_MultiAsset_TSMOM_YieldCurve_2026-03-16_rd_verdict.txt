STRUCTURAL ROOT CAUSE ANALYSIS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The walk-forward framework requires each OOS window to have ≥272 trading days, but the
standard 6-month OOS windows provide only ~124–127 days. Every single WF window errored.
This is not a tuning issue — it is a fundamental incompatibility between the strategy's
lookback requirements and the WF validation methodology.

The same incompatibility surfaces in regime-slice analysis: rate_shock_2022 (1 year = ~251
days) and normalization_2023 (~250 days) both fail the minimum data requirement. This means
the strategy cannot be properly stress-tested against the rate-shock regime at all.

This structural problem has persisted across all three H07 iterations:
  H07:  IS Sharpe insufficient; OOS degraded
  H07b: Added multi-asset expansion; OOS ceiling ~0.85; WF incompatible
  H07c: Added YC regime filter + dynamic lookback; IS Sharpe degraded to 0.8481; WF still
        structurally incompatible with standard validation framework

The yield curve filter, while conceptually sound for suppressing rate-shock drawdowns, reduced
entry opportunities further (7.6% IS block rate, 17.9% OOS block rate) and degraded the IS
Sharpe. The filter was intended to improve OOS stability, but the OOS data shows 56.9% of OOS
days had an inverted yield curve, causing the filter to be highly active precisely when the
strategy would otherwise have been generating trades. This structural conflict between the filter
design and the OOS environment is likely the primary driver of the performance degradation.
